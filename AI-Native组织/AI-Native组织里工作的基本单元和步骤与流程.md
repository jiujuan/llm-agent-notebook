先给结论：

> AI Native 组织不是取消市场、产品、销售、营销、售后等职能，而是把这些职能从“部门分工”重新编排成一条条由人和 Agent 共同运行、可以持续评估和优化的端到端价值流。

Agent 不是最基本的工作单元。**Agent 是工作执行者之一；目标、工作流、决策与责任才是组织设计的核心。**

## 一、AI Native 组织的基本工作单元

可以把基本单元分成四层。

| 层级   | 基本单元               | 作用                             |
| ------ | ---------------------- | -------------------------------- |
| 经营层 | Outcome 业务结果       | 定义组织最终要得到什么           |
| 组织层 | Value Stream 价值流    | 串联跨部门活动，完成某类客户价值 |
| 运行层 | Workflow 工作流        | 规定一次业务如何从触发走向交付   |
| 执行层 | Task、Decision、Action | 完成具体任务、判断和系统操作     |

支撑这些工作的还有六类基础单元：

| 支撑单元    | 作用                                 |
| ----------- | ------------------------------------ |
| Human Owner | 对目标、流程和最终结果负责           |
| Agent       | 研究、规划、生成、执行、监控或协调   |
| Context     | 为当前任务提供客户、业务和历史背景   |
| Tool        | 让 Agent 操作 CRM、ERP、代码库等系统 |
| Memory      | 保存历史经验、状态、偏好和反馈       |
| Evaluation  | 判断输出是否正确、有效、安全         |
| Guardrail   | 限制权限、风险和可执行范围           |

### 1. Outcome：业务结果

Outcome 是最高层工作单元，例如：

- 获得100个合格商机
- 将产品从需求推进到正式发布
- 将客户问题解决时间降到2小时
- 提升续约率
- 降低产品缺陷率

AI Native 组织不以“完成了多少动作”为最终标准，而以业务结果作为工作起点。

### 2. Value Stream：价值流

价值流是从需求或机会出现，到客户价值实现的完整链条。例如：

> 市场机会发现 → 产品定义 → 产品开发 → 上市营销 → 销售转化 → 交付 → 客户成功 → 续约

传统企业往往把它切给不同部门；AI Native 组织更强调对整条价值流负责。

### 3. Workflow：工作流

工作流是可重复运行的业务过程，必须具有：

- 明确的触发条件
- 输入和输出
- 执行步骤
- 人与 Agent 的职责
- 权限和风险边界
- 质量标准
- 异常升级机制
- 业务指标

例如“销售线索跟进”不是一个 Agent，而是一条包含数据收集、客户研究、评分、触达、回复判断和人工接管的工作流。

### 4. Task：任务

Task 是最小的可执行工作单元，例如：

- 检索客户资料
- 分析一次访谈
- 生成产品需求草案
- 检查一份合同
- 回复一个工单

任务适合分派给人或 Agent，但任务本身通常不承担完整业务结果。

### 5. Decision：决策

决策是最容易被忽略、却非常关键的单元，例如：

- 是否把线索升级为商机
- 是否开发某个需求
- 是否批准折扣
- 是否发布产品
- 是否向客户赔偿

低风险、规则明确的决策可以交给 Agent；高风险、不可逆或责任重大的决策必须由人批准。

### 6. Human-Agent Pod：人机任务小组

这是AI Native组织比较理想的基本组织单元：

> 一个业务 Owner + 若干专业人员 + 若干 Agent + 一组共享工具和评价体系

它不一定是固定部门，可以围绕获客、产品发布、客户续约等目标动态组成。

## 二、哪些单元最重要

按重要性排序，我认为是：

1. **Outcome**：没有明确结果，Agent只会制造更多活动。
2. **Workflow**：它决定人、Agent、数据和工具如何真正协作。
3. **Human Owner**：确保结果始终有人负责。
4. **Decision**：决定哪些权力可以交给AI，哪些必须留给人。
5. **Evaluation**：没有评价系统，就无法知道Agent是在创造价值还是稳定地产生错误。

Agent反而不是第一位，因为模型、框架和供应商都可以替换。一个组织真正可积累的资产是：

> 工作流、数据、上下文、评价体系、业务规则和运行反馈。

## 三、AI Native工作的标准步骤

一条完整的AI Native工作流通常包括十步：

```
业务事件触发
→ 理解目标与约束
→ 获取上下文
→ 制定执行计划
→ 分配给人或Agent
→ 调用工具执行
→ 检查事实与质量
→ 人工审批或异常接管
→ 交付业务结果
→ 监控效果并更新记忆、规则和评价集
```

其中有三个闭环。

- **执行闭环**：触发 → 执行 → 检查 → 交付
- **管理闭环**：目标 → 指标 → 监控 → 异常处理
- **学习闭环**：结果 → 反馈 → 归因 → 更新工作流

传统流程通常是“设计一次，重复执行”；AI Native流程更接近“每次运行都留下数据，并持续学习”。

## 四、与传统职能的逐项关系

### 1. 市场开发

传统工作主要是行业研究、寻找市场机会、合作拓展和线索获取。

AI Native模式：

> 市场信号监测 → 趋势识别 → 客群发现 → 机会评分 → 方案生成 → 人工判断 → 小规模验证

Agent负责持续扫描行业、客户、竞品和渠道数据，生成机会假设；人负责判断市场结构、建立合作关系和承担投资决策。

主要变化：

- 从周期性市场调研变成持续市场感知
- 从人工找机会变成Agent发现、人验证
- 从研究报告变成可测试的机会组合
- 指标从“报告和线索数量”转向机会命中率、验证速度和商机价值

### 2. 产品开发

传统流程通常是需求收集、立项、设计、开发、测试和发布，部门交接较多。

AI Native模式：

> 反馈自动汇聚 → 需求聚类 → 问题验证 → 方案生成 → 原型/代码生成 → 自动测试 → 人工发布决策 → 线上反馈

Agent可以分析访谈、生成PRD、创建原型、编写代码和测试；人负责问题定义、产品取舍、架构判断、体验标准和上线责任。

主要变化：

- 从文档驱动转为证据和实验驱动
- 从大批量排期转为小步验证
- 产品、设计、开发边界变弱
- 指标转向需求验证周期、实验成功率、交付周期和客户价值

### 3. 产品销售

传统销售依赖销售人员寻找线索、维护CRM、准备方案、跟进和谈判。

AI Native模式：

> 线索发现 → 自动研究 → 意向评分 → 个性化触达 → 回复识别 → 销售接管 → 方案生成 → 成交预测

Agent适合处理研究、录入、提醒、材料准备和常规跟进；人主要处理信任、复杂需求、谈判、承诺和关键客户关系。

主要变化：

- 销售不再把大量时间用于搜集和录入信息
- Agent可以同时维护更大的潜在客户池
- 人在客户出现购买信号时介入
- 指标增加Agent线索接受率、人工接管率、建议采纳率和单位获客成本

### 4. 产品营销

产品营销负责定位、信息表达、上市、内容、渠道和需求创造，与市场开发并不相同。

AI Native模式：

> 客群洞察 → 定位假设 → 内容生成 → 多渠道投放 → 个性化适配 → 数据归因 → 策略调整

Agent可以生成大量内容和变体，但人必须把握品牌、核心叙事、文化语境和长期市场定位。

主要变化：

- 从单一内容面向所有客户，变成基于场景的动态内容
- 从季度复盘变成近实时归因和优化
- 内容生产成本下降，判断和差异化的重要性上升
- 指标从曝光量转向有效需求、信息匹配度、转化率和品牌一致性

### 5. 售后

售后重点处理购买或交付后的故障、退换、维修、投诉和质保。

AI Native模式：

> 问题识别 → 客户身份与产品状态确认 → 知识检索 → 初步诊断 → 自动处理或人工升级 → 结果确认 → 根因归档

Agent适合7×24小时受理、分类、检索和标准处置；人负责情绪冲突、复杂故障、赔偿和重大客诉。

主要变化：

- 从排队响应转为即时分诊
- 从客服人员查知识库转为Agent主动组织答案
- 从解决单个问题转为自动聚类并发现产品缺陷
- 指标包括首次解决率、升级率、误答率、解决时间和客户满意度

### 6. 客户服务与客户成功

服务比售后范围更广，关注客户能否持续获得价值，包括培训、采用、运营建议、续约和增购。

AI Native模式：

> 使用行为监测 → 健康度判断 → 风险预警 → 个性化建议 → 客户经理介入 → 价值复盘 → 续约或增购

Agent负责持续监测、提醒和生成建议；人负责理解客户组织、建立信任、协调资源和制定成功计划。

主要变化：

- 从客户主动报问题转为组织主动发现风险
- 从统一服务转为个性化服务
- 从售后成本中心转为客户价值与续约中心
- 指标包括产品采用率、价值实现时间、流失预警准确率、续约率和扩展收入

## 五、传统组织与AI Native组织的本质区别

| 传统组织               | AI Native组织                  |
| ---------------------- | ------------------------------ |
| 围绕部门划分工作       | 围绕业务结果和价值流组织工作   |
| 人是默认执行者         | 人和Agent按能力、风险动态分工  |
| 工作依赖会议和交接     | 工作依赖共享状态和事件触发     |
| 信息保存在人脑和文档中 | 上下文、规则和记忆可被系统调用 |
| 管理者分配具体任务     | 管理者设计目标、边界和评价系统 |
| 出错后人工追责         | 全程记录、评估、审计和异常升级 |
| 定期复盘流程           | 流程根据反馈持续更新           |
| 部门指标优先           | 端到端客户结果优先             |

不过，AI Native组织不会让传统专业消失。市场判断、产品判断、销售关系、品牌表达和客户信任仍然需要专业人员。真正发生变化的是：**专业能力从大量亲自执行，转向定义标准、处理例外、训练系统和承担结果。**

最终可以把AI Native组织概括为：

> 以Outcome为方向，以Value Stream为组织边界，以Workflow为运行载体，以Task和Decision为执行单元，以Human Owner承担责任，由Agent完成可委托工作，并通过Evaluation形成持续学习闭环。
